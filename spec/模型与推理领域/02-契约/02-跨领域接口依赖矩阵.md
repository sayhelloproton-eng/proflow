# 11 · 跨领域接口依赖矩阵

## 1. 总矩阵

| 调用方 | 典型需求 | Model 输入 | Model 输出 | 最终决定归属 |
|---|---|---|---|---|
| Execution Runtime | mutation risk / evidence conflict | typed execution facts | ALLOW/DENY/ESCALATE judgment | Execution |
| Extension Browser Carrier Controller | page ambiguity / recovery | DOM facts + optional image | page/recovery judgment | Carrier Controller / Execution browser effect boundary |
| Extension Task Diagnostic | exceptional single-Task ambiguity | bounded Task/Execution/Carrier facts | diagnostic finding/recommendation | Task/Owner facts unchanged |
| Extension System Observer | whole-system assessment | 8 bounded system views / batch summaries | assessment/findings/risks | 只评估/请求，不执行或改 Owner facts |
| Agent Runtime | extraction/classification/deep reasoning（按需） | Agent-owned context | typed cognition result | Agent |
| Task | v1 通常不直接调用 | — | — | Task |
| Deployment | capability verify / doctor | test case | capability result | Deployment 执行验证，Model 定义合格标准 |

## 2. [FROZEN] Execution 调用约束

Execution 先执行 deterministic hard rules。

只有需要认知判断时才调用 Model。

Model ALLOW 不覆盖：

- hard DENY；
- scope；
- mandatory approval；
- precondition。

## 3. [FROZEN] Extension System Observer / Task Diagnostic 优先级

System Observer 调 Model 必须使用 `background`，并保持 Extension 最低优先级；业务请求存在时 background 只能排后。Task Diagnostic 只在单 Task deterministic facts 无法安全判定时进入 REASON，正常 READY/result/reply/reopen progression 不调用模型。

## 4. [FROZEN] Agent 调用

Agent 不把整个 Conversation 隐式交给 Model Runtime；必须形成当前 Spec 需要的 typed input。

## 5. [FROZEN] Model 不反向依赖业务 Public API

Model Runtime 不为“补全上下文”去调用 Task/Agent/Execution Public API。

这避免循环依赖：

```text
Execution → Model → Execution
```

只能发生在调用方显式下一轮，而不是 Model Runtime 内部自调用。

## 6. [FROZEN] Deployment 边界

Deployment 最后统一：

- Provider config；
- credential；
- FAST/REASON model mapping；
- capability profile config；
- service lifecycle；
- verify/doctor。

Model Domain 只提供 contracts 与合格判据。

---

## 当前正式约束：无反向业务依赖

Model contracts/runtime package 不依赖 Task/Agent/Execution/platform-host。Execution/Agent/Task 通过 Model Public Contract 调用；Deployment 通过 Module lifecycle/verify 管理。Provider 作为 External Resource Module，由 Deployment materialize config，Model 只消费解析后的合法配置/moduleRef。
