# 15 · 新仓库实现顺序与停止门

## 1. 目标

用最少增量把 Model Domain 做成其他领域可依赖的稳定算力，不追求功能数量。

## 2. [RECOMMENDED] 实现顺序

### Step 1 — `model-contracts`

实现：

- InferenceRequest/Result/Error；
- RuntimeStatus；
- ReasoningSpec contract；
- CapabilityProposal contract；
- runtime schemas。

**停止门**：`tsc --noEmit` + Contract tests PASS。

### Step 2 — Spec + Prompt Renderer

只实现 1~2 个真实 Spec，例如：

```text
execution.command-risk.v1
browser.page-state.v1
```

**停止门**：typed input→deterministic prompt→typed output validator PASS。

### Step 3 — Provider Adapter + FAST

只接一套真实 API provider，跑 FAST text/structured。

**停止门**：M2 FAST PASS。

### Step 4 — Resource Coordinator + queue

单 Lane + business/background + queue timeout。

**停止门**：并发请求真实串行，background 让路。

### Step 5 — REASON + AUTO

加入 REASON mapping 和一个允许 AUTO escalation 的 Spec。

**停止门**：FAST/REASON 不静默替换，AUTO 只按 Spec 升级。

### Step 6 — Vision

加入 image ContextPart 与真实 image model verification。

**停止门**：不支持 image 时明确 `CAPABILITY_UNSUPPORTED`；支持时 M2 Vision PASS。

### Step 7 — Proposal bridge test

模型输出一个 constrained Capability Proposal，调用测试中间层校验，再送 Execution mock/real contract。

**停止门**：未知 capability / bad args 均不能进入 Execution。

### Step 8 — Logs / Health / M3 / M4

补齐 structured logs、RuntimeStatus、scenario regression、serial stability。

**停止门**：Model Runtime 才可标记 ProFlow P0 READY。

## 3. [FROZEN] 防过度设计停止门

实现中如有人提出新增：

```text
service
entity
database
persistent scheduler
provider plugin system
prompt platform
metrics platform
```

必须先证明当前 P0 存在真实阻塞。不能以“以后会需要”为理由加入。

## 4. 实验资产复用时机

只有当前 Public Contract 冻结后，才允许评估任何实验实现：

```text
REUSE AS-IS
REFACTOR & ADAPT
REWRITE
DROP
```

不能为了复用实验代码而改变当前领域合同。

### Step 9 — Task Diagnostic / System Assessment Contract Proof

在不新增 Model 业务 Store / Observer Runtime 的前提下，补齐两类调用方场景：

```text
Task-level diagnostic REASON
System-level bounded assessment REASON
```

必须证明：

- 正常 Task progression 不调用模型；
- System Observer 以 background priority 调用，不阻塞 business lane；
- caller 负责 bounded snapshot、batch、carry-forward、drill-down 与 global synthesis orchestration；
- Model Runtime 只执行 versioned ReasoningSpec + typed inference，不保存 System Assessment 业务事实；
- 手机 REASON 无法一次稳定承载全量输入时，按真实有效负载缩小 batch；
- 模型 unavailable/busy/server_paused 时 assessment/diagnostic 可 defer，Task 主链不损坏。

**停止门**：出现“System Observer Engine/Store/Scheduler”进入 Model Domain，或模型结果直接写 Task/Execution owner facts，立即 STOP。
