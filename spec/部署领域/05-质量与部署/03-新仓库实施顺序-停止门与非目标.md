# 新仓库实施顺序、停止门与非目标

## 1. 固定实施顺序

```text
R1 Docs truth
→ R2 Module resources
→ R3 Platform CLI refactor
→ R4 Tests + simulated human Golden Path
→ STOP
```

不增加第五批。

## 2. R1 STOP gate

权威文档中 removed CLI 作为当前行为 = 0；Core/installRequires 安装模型 = 0；uninstall 删除 `.proflow` = 0；Platform-owned Module status/validation = 0。

## 3. R2 STOP gate

24/24 governed package 对齐；15/15 config-bearing package 有配置指导；status descriptor/adapter mismatch = 0；Platform service-process dependency = 0。

若需要真实业务领域重设计：`DOMAIN_BLOCKER`。

## 4. R3 STOP gate

exactly six commands；old routes = 0；install Plan/Apply paths = 0；Core/install closure = 0；Platform-owned Module health/preflight = 0；service-process callers = 0；uninstall `.proflow` deletion = 0；global binding route dependency = 0。

## 5. R4 STOP gate

obsolete test expectations = 0；critical six-command failures = 0；Module governance failures = 0；simulated human Golden Path blocker = 0。

## 6. 非目标

- 不重新设计 Browser/Model/Execution/Gateway/Task 领域；
- 不增加 CLI；
- 不恢复 repair/retry/rollback/resume engine；
- 不把 package manager dependency resolution 搬进 Platform；
- 不做真实 Registry publish；
- 不在 simulated acceptance 后继续无限整改。
