# 测试门禁与真实验收

## 1. 当前目标

测试只证明冻结的七命令与 Module Governance，不再要求旧 Plan/Apply/Upgrade/Preflight/Verify/Doctor/Manifest 产品行为。

## 2. R2 Contract / Package governance

必须证明：

- 24/24 governed Module 提供 `install/uninstall/status/setup/docs/start/stop`；
- 24/24 root manifest 与 runtime descriptor 一致；
- status shape = `setupStatus/runtimeStatus`；
- 24/24 有 `DOCS.md` 与 `SETUP.md`；
- 标准 guidance 中 `CONFIGURATION.md` = 0；
- deterministic/private/shared-fact 配置不暴露成人工配置；
- legitimate Module-specific extra commands 不被删除。

## 3. R3 Platform CLI

必须证明：

- top-level Platform commands = 7；
- `platform modules` / old routes = 0；
- install = package sync + Module.install；
- uninstall = Module.uninstall + package remove；
- status/setup/docs 只 generic forward/aggregate；`platform setup` 必须遍历全部 Module，不得在首个 ACTION_REQUIRED/FAILED 停止；
- start 只以 Module.status.setupStatus 为 gate，不调用 preflight/validate；
- stop 逆依赖顺序；
- `configByModuleRef` / private config loader / production binding middleman = 0。

## 4. R4 Tests / Acceptance

旧测试若编码已删除 management 行为，应删除/重写 management assertion，不得改业务代码去满足旧测试；同一测试文件里的业务、安全、runtime proof 不得弱化。

## 5. Simulated Human Golden Path

```text
Fresh Workspace
→ platform install
→ platform status
→ platform docs
→ platform setup
→ simulate ACTION_REQUIRED completion
→ platform setup
→ platform status
→ platform start
→ platform status
→ platform stop
→ platform uninstall
```

验证 setup 可重入、全量聚合、READY 跳过、自动步骤继续执行、所有人工引导一次列全；同时验证每个需要 setup 的 Module 的 `SETUP.md` 为最短 Step 闭环，状态推进 Step 均具备 package-owned executable/verify；status 保持单一真源且没有隐藏 preflight/repair/Plan/Apply。

## 6. Final gate

```text
TESTS_ALIGNED = YES
SIMULATED_HUMAN_E2E = PASS
READY_FOR_HUMAN_ACCEPTANCE = YES
```

达到后强制 STOP，由用户进行真实人工验收；不得再发散出新一轮系统性 residual audit。

## 7. Scope rule

不阻塞当前冻结 Gate 的问题只记录 `OUT_OF_SCOPE_DOMAIN`；缺 Producer-owned shared fact 记录 `SHARED_FACT_CONTRACT_MISSING`；不得通过修改业务领域或重建 Platform config bus 绕过。
