# 测试门禁与真实验收

## 1. 当前目标

测试只证明冻结的六命令与 Module Governance，不再要求旧 Plan/Apply/Upgrade/Verify/Doctor/Manifest 产品行为。

## 2. 分层门禁

### R2 Contract / Package governance

证明：

- 24/24 governed package metadata 不含 active `installClass/installRequires`；
- status observation shape 正确；
- Runtime provides/requires graph 可解析；
- 15/15 config-bearing Module 有足够配置指导；
- 运行型 package 可由 package-owned production binding 承担 lifecycle。

### R3 CLI

证明：

- top-level commands = 6；
- removed commands routable = 0；
- install 不经过 Plan/Apply；
- uninstall 不删除 `.proflow`；
- modules/docs 只聚合 Module facts；
- start 全 validate 在任何 start 前完成，fail-fast；
- stop 逆依赖顺序 fail-fast；
- Platform service-process/global binding old route caller = 0。

### R4 Tests / Acceptance

旧测试若编码已删除产品行为，应删除/重写，不得改新代码去满足旧测试。

## 3. Simulated Human Golden Path

```text
Fresh Workspace
→ platform install
→ platform modules
→ platform docs
→ follow Module docs to configure
→ platform start
→ platform modules
→ platform stop
→ platform uninstall
```

验证 `.proflow` 在 uninstall 后仍存在，且没有隐藏 stop/repair/Plan/Apply。

## 4. Final gate

```text
TESTS_ALIGNED = YES
SIMULATED_HUMAN_E2E = PASS
READY_FOR_HUMAN_ACCEPTANCE = YES
```

达到后强制 STOP，由用户进行真实人工验收；不得再发散出新一轮系统性 residual audit。

## 5. Scope rule

不阻塞当前冻结 Gate 的问题只记录 `OUT_OF_SCOPE_DOMAIN`；若必须重设计业务领域才能过 Gate，则 `DOMAIN_BLOCKER` 并停止扩散。
