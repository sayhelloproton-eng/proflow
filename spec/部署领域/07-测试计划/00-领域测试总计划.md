# Deployment Domain 测试总计划

## Purpose

证明当前 Module Governance 与七命令 Platform CLI 的产品真源已真实落地。

## Coverage

1. Module Contract：七标准能力、topology、public config boundary、status observation、DOCS/SETUP。
2. Module Template：所有 profile 生成七能力与两标准文档，不恢复旧管理面。
3. Module Skill：AI guidance 遵守 install/shared-fact/setup 三分法。
4. Deployment Conformance：24 package 治理一致性。
5. Platform CLI：install/uninstall/status/setup/docs/start/stop targeted tests。
6. Simulated Human Golden Path：Fresh Workspace 完整人工路径模拟。

## Removed product behavior

不建立 Platform Plan/Apply/resume、Upgrade、modules、Preflight/Validate、Verify/Doctor/Manifest acceptance tests。Module-specific 真实 extra verification 不受影响。

## Final acceptance

```text
critical targeted tests PASS
narrow full gates PASS
simulated human E2E PASS
→ READY_FOR_HUMAN_ACCEPTANCE
```

任何测试若必须修改业务领域语义才能通过，立即 `DOMAIN_BLOCKER`；不得为了测试扩散业务重构。

## Setup closure invariant

`platform setup` 必须全量扫描并聚合所有未 READY Module；每个 owning Module 的 `SETUP.md` 与 `Module.setup` 必须给出最短闭环，能自动的步骤自动完成，真正人工步骤提供 package-owned executable/verify，最终以 `Module.status.setupStatus=READY` 为完成条件。

依赖 gating 必须保持 generic：当前 Module 只有在全部 required provider 的本次真实 `setupStatus=READY` 时才允许调用 `Module.setup`；provider 未 READY 时 dependent 只记录为 `BLOCKED` 且 setup 调用次数为 0，但其它独立 Module 继续扫描。provider 的 setup 执行后必须重新读取 `Module.status`，不能根据 setup command 返回值猜 READY；若同一次调用中 provider 已 READY，排序在后的 dependent 可以继续。

Platform 仍只做 discovery / dependency ordering / standard status observation / forwarding / aggregation，不理解 Chrome、Custom GPT、Knowledge、model、Auth、g-id 等业务事实，不增加 moduleRef-specific branch、config bus、持久化 resume state 或新的顶层命令。Real-2 Custom GPT Deployment Provisioning 的跨域真实验收继续服从 Agent/Execution 专项计划。
