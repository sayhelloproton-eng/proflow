# Deployment Domain 测试总计划

## Purpose

证明当前 Module Governance 与七命令 Platform CLI 的产品真源已真实落地。

## Coverage

1. Module Contract：七标准能力、topology、public config boundary、status observation、DOCS/SETUP。
2. Module Template：所有 profile 生成七能力与两标准文档，不恢复旧管理面。
3. Module Skill：AI guidance 遵守 install/shared-fact/setup 三分法。
4. Deployment Conformance：24 package 治理一致性。
5. Platform CLI：install/uninstall/status/setup/docs/start/stop targeted tests。
6. Simulated Human Golden Path：Fresh Workspace 完整人工路径模拟。

## Removed product behavior

不建立 Platform Plan/Apply/resume、Upgrade、modules、Preflight/Validate、Verify/Doctor/Manifest acceptance tests。Module-specific 真实 extra verification 不受影响。

## Final acceptance

```text
critical targeted tests PASS
narrow full gates PASS
simulated human E2E PASS
→ READY_FOR_HUMAN_ACCEPTANCE
```

任何测试若必须修改业务领域语义才能通过，立即 `DOMAIN_BLOCKER`；不得为了测试扩散业务重构。

## Setup closure invariant

`platform setup` 必须全量扫描并聚合所有未 READY Module；每个 owning Module 的 `SETUP.md` 与 `Module.setup` 必须给出最短闭环，能自动的步骤自动完成，真正人工步骤提供 package-owned executable/verify，最终以 `Module.status.setupStatus=READY` 为完成条件。Platform 只做 discovery / ordering / forwarding / aggregation，不解释具体配置。
