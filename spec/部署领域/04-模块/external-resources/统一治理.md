# 外部资源 Module 统一治理

## 1. 强制原则

> 任何进入平台运行链、部署链或验证链的外部资源，都必须以 Module 方式进入 Module Graph。

禁止：

```text
model-runtime README 里偷偷写一个 API endpoint
execution README 里偷偷依赖 Chrome
agent README 里偷偷要求 ChatGPT GPT 配好
```

这些都必须变成受 Module Governance 管理的 External Resource Module，并统一提供 `install/uninstall/status/setup/docs/start/stop`。Platform 只发现、排序、转发和聚合；`platform setup` 一次收集所有 External Resource 未 READY 项。真实外部配置与人工动作归 owning Module.setup；每个资源包必须给出最短 Step、package-owned executable/verify 与成功条件，优先自动完成一切可自动动作。

## 2. Adapter Pattern

```text
External Resource
  ↑ API / CLI / OS integration
External Resource Module Adapter (npm package)
  ↑ module-contract
platform-cli
```

Adapter 负责翻译，不拥有外部产品。

## 3. P0 外部资源示例

### Model API Provider Module

提供逻辑 contract，例如通用 `model.provider.api`；provider URL / credential / model choice 等真实外部输入由 `Module.setup` 管理，`Module.status` 观察当前 readiness。若 package 还提供深度 capability verification，它是 Module-specific extra capability，不成为 Platform 第二套 verify gate。

### Dev Tunnel Module

`Module.install` 只处理可确定的本地资源；Microsoft 登录、Tunnel 创建/选择、public URL 等进入 `Module.setup`；`Module.status` 返回当前真实状态，start/stop 仅由 Module 自己实现真实控制。

### Chrome Runtime Module

自动探测可由 install/status 自闭环；需要用户选择 Chrome path、授权或加载 Extension 时由 `Module.setup` 返回 `ACTION_REQUIRED`。

### ChatGPT Carrier Module

ChatGPT Web/Custom GPT 的登录、创建、Action/Auth/能力配置与真实验证由 `Module.setup` 引导并重新观察现实；不能伪造在线状态。Agent Package 自己保留角色/Custom GPT 等真实额外能力。

对于 v1 Custom GPT + Actions，Carrier Module/Agent Package requirements 至少能够验证或引导：

```text
Actions enabled
static OpenAPI installed
Action auth valid
File Bridge required/optional
Code Interpreter required/optional
Web Search required/optional
Apps disabled when Actions are the P0 tool chain
recommended model only advisory
```

Role READY 依据真实配置能力 + Action E2E，不依据精确 ChatGPT model id。

## 4. 七标准能力与真实主义

所有 External Resource Module 都提供七标准能力：`install/uninstall/status/setup/docs/start/stop`。

这些标准入口必须由 Module 自己解释真实能力：没有独立 runtime 的资源，其 `start/stop` 可以成功 no-op，`runtimeStatus=NOT_APPLICABLE`；需要人工或外部系统参与时由 `setup` 返回 `ACTION_REQUIRED`，但不得在一个资源阻塞后阻止 Platform 收集其它资源引导；无法自闭环的内部失败返回 `FAILED`。

Module-specific `verify/doctor/restart/probe` 等额外能力可以保留，但 Platform 不代理、不把它们升级成标准 lifecycle 或 start gate。

## 5. Setup 最短闭环

External Resource 的 setup 默认追求最快 READY，而不是把外部产品复杂度暴露给用户：

```text
auto-detect / auto-materialize what the Module can own
→ prepare all materials before asking the user
→ ask only the irreducible external/human action
→ package-owned verify immediately after the action
→ publish current shared facts/status
→ setupStatus=READY
```

每个 `SETUP.md` Step 都必须有 package-owned executable/verify。登录、Custom GPT Web、Chrome UI 等无法完全自动化的步骤，也必须由 package command 负责 prepare 所需材料并在用户完成后 verify；不得让用户自行理解内部 path/token/endpoint 或手工复制 Producer-owned shared fact。允许一个命令完成多个自动步骤，优先减少用户往返。

## 6. External Version

Adapter version 与 Resource version 分离；避免“Adapter 1.2.0”被误认为“Chrome 150”或“远端 API 版本”。

## 7. External Upgrade

没有独立 Platform Upgrade Plan。Adapter package 版本同步仍由 `platform install` + package manager 负责；external resource 自身 upgrade/check、credential migration、human action、post-upgrade verification 由 owning Module 的 `setup` 或 Module-specific extra capability 负责。

Platform CLI 不假定所有外部资源都可自动升级，也不建立统一 external-resource upgrade state machine。

## 8. Bootstrap 例外

最小 Node/npm/OS 是 Platform CLI 启动根。初始 bootstrap 完成后，它们可以继续被对应 External Resource Module 纳入状态/验证治理。这个例外只解决“CLI 尚未存在时谁部署 CLI”的无限递归，不允许成为永久旁路。

---

## 当前正式约束：统一外部依赖

Dev Tunnel、Chrome Runtime、ChatGPT Carrier、Model Provider API 全部必须作为 External Resource Module 纳入同一 Module Graph。External adapter 的七标准能力必须基于真实可观察/可控制现实实现；无法控制的独立 runtime 通过 `NOT_APPLICABLE` 表达，不伪造 RUNNING。FAST/REASON 不作为 Provider Module identity；Provider 只提供通用 `model.provider.api` capability。

## 9. OpenAI Actions / Public Ingress 的外部约束

Custom GPT Carrier 与 public-ingress Module 的真实 setup/status 或其 Module-specific verification extra 必须覆盖 OpenAI 当前 production hard contract：

```text
TLS 1.2+
public HTTPS / port 443
Action request/response < 100,000 chars
45s round-trip ceiling
real 429/5xx
file relay reachable
```

Carrier-specific conditional checks：

```text
Workspace action-domain allowlist（适用工作区时）
Privacy Policy URL（公开 GPT + Actions 场景需要时）
Action auth（包括 GPT version restore/upgrade 后重新验证）
```

这些只进入 ChatGPT Carrier / public-ingress External Resource Module，不扩展成新的 Deployment Service。
