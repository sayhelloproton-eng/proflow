# 领域宪章与边界

## 1. Charter

Deployment Domain 是平台的软件落地与运行装配层，也是所有 ProFlow Module 的统一工程治理入口。

它只回答：Module 是否合规、package 如何进入/退出 Workspace、Module 如何 install/setup/status/docs/start/stop、依赖按什么顺序调用，以及 Contract/Template/Conformance 如何保持一致。

## 2. AI 与 CLI

AI 读取 Module docs、执行 Platform 七命令、根据 `Module.setup` 的结构化结果指导用户；不靠猜测 configSlots 生成临时安装流程。

CLI 只做确定性 discovery、ordering、forwarding、aggregation 和 package-manager orchestration。Platform 不实现 Module 私有 validation/config/runtime truth。

## 3. 与四领域边界

### Task & Orchestration

Deployment 只负责 Task packages 的 package/Module lifecycle 接缝；Task 状态机、Node、Task 文档、store 业务语义不归 Deployment。

### Agent Runtime & Collaboration

Deployment 只负责 Agent/Gateway/Carrier Module 的 install/setup/status/start/stop 接缝；Role/Worker/Conversation/Message Center 业务事实归 Agent。

### Execution

Deployment 只负责 Execution Runtime / Browser Extension / Chrome Module 的标准管理能力；Execution Policy、Effect、Evidence、UNKNOWN_SIDE_EFFECT 归 Execution。

### Model & Reasoning

Deployment 只负责 Model Runtime / Provider Module 的标准管理能力；推理路由、Reasoning Spec、Capability Proposal 归 Model。

## 4. Config / Shared Fact 边界

- Module 能唯一确定的值由 `Module.install` 自闭环；
- 跨 Module 值经 Producer-owned Contract/shared fact；
- 用户选择或外部现实进入 `Module.setup`；
- Platform 不读私有 config、不复制 provider value、不作为 config bus。

## 5. 硬边界

- 不把 Logical Service 自动等价成 Process；
- 不让 Deployment 重新定义其他领域业务 Contract；
- 不让外部资源绕过 Module Governance；
- 不让 Module Skill 绕过 Conformance；
- 不建立 `configStatus/missingConfig` 第二状态模型；
- 不恢复 Platform preflight/verify/doctor/repair；
- 不为本重构建设 rollback/retry/resume engine。
