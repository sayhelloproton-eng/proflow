# 智能体运行与协作领域｜失败恢复、版本、安全与 v1 验收

---

# 1. 总原则

```text
Owner validates its own business facts
model error cannot bypass service legality
all cross-domain access uses Public Contracts
Browser irreversible effects need stable intent + Receipt
unknown side effect is never blindly retried
Task terminal is final
Worker identity is Task-scoped
```

---

# 2. 身份模型

## Custom GPT

```text
one Role → one Bearer Key
Bearer Key → Gateway → authenticatedRoleRef
```

不信任 body 自报 roleRef。

## Browser Extension

```text
Browser Extension → local-platform-token → Execution Runtime Browser protocol surface
```

不得使用 Role Key 冒充 Agent。

## Task-scoped Worker

服务端对涉及 Task 的角色 Action 校验：

```text
authenticatedRoleRef
+ taskId
+ workerRef
+ TaskRoleBinding(agentPackageRef/roleRef/workerRef/conversationLocator)
+ Node.requiredAgentPackageRef + current runNo（按接口）
```

不同 Task 不复用同 Worker Conversation。

---

# 3. Secret

MUST NOT：

```text
Git
Knowledge
OpenAPI example
Task Markdown
logs
browser injected text
Execution readable local-resource result
```

v1 secret 存 `.proflow` 受限文件。

支持：

```text
show-role-key (explicit local user action)
rotate-role-key
```

rotate 不改变 roleRef。

---

# 4. Role 注册/删除恢复

注册：

```text
validate g-id/url
→ write Role Registry
→ generate role key
→ validate registry+credential pair
→ guide Web auth
```

若 registry/key 半完成，`Module.status` / `Module.setup` 必须检测并 fail-closed；`role validate` 等 Agent Package extra command 也可提供更深诊断，不得宽松认证。

删除：

```text
role delete
→ Task Public API query non-terminal role usage
→ in use: ROLE_IN_USE, zero mutation
→ not in use: physical delete role entry + secret
```

v1 无 tombstone/logical delete。

终态 Task 中既有 roleRef 保留，但 Agent Registry 可返回 ROLE_NOT_FOUND。

---

# 5. New Task 三 Worker 初始化失败恢复

冻结顺序：

```text
Extension New Task
→ Task.createTask(PENDING)
→ Browser CREATE/observe Product + Dev + Test Conversations（可并发）
→ Agent/Carrier validate observed role/Conversation identity semantics
→ Task.bindTaskWorker(each packageName) as durable binding truth
→ Product一旦绑定即可Requirement discussion/write
→ Dev/Test WORKER_BIND only + IDLE
→ 3 bindings + Requirement + prerequisites → READY
→ human confirmation channel → startTask
```

失败例：Product/Dev 已绑定，Test CREATE失败。

恢复必须：

```text
read current TaskRoleBindings
→ preserve Product/Dev
→ only CREATE/bind missing Test
→ do not duplicate existing Conversation
```

Task READY/startTask只依赖稳定binding/readiness，不依赖三个tab当前存活。

# 6. WORKER_BIND 安全

`WORKER_BIND`：

```text
create/identify Conversation
associate task/role/worker
```

MUST NOT：

```text
completeNode
execute dev/test task body
reopen/wait for unready node
perform business side effects
```

正式工作只能由：

```text
NODE_READY
REOPEN
```

触发。

# 7. Action 调错防御

```text
1. role package static Action surface
2. clear OpenAPI operation semantics
3. Gateway auth/schema validation
4. downstream Owner state/version/policy validation
```

不能依赖“LLM 一般不会选错”。

# 8. Collaboration 幂等/顺序

`askPeer/replyPeer` 必须带 `idempotencyKey`。

```text
same key + same semantic request → same response
same key + different request → IDEMPOTENCY_CONFLICT
```

Thread：

```text
Q1 PENDING/DELIVERED
→ A1 durable
→ A1 Browser DELIVERED back to asker
→ only then Q2 allowed
```

Reply 仅 durable 不够。

同一 Task 参与者才可问答；reply target 自动来自 thread。

---

# 9. Collaboration Delivery

Extension 以稳定：

```text
messageId
```

作为真实 Browser delivery intent。

必须：

```text
verify expected roleRef + workerRef
idempotent/effectively-once submit strategy；不承诺端到端 exactly-once
receipt/result refs
uncertain side effect → reconcile before retry
```

Message Center 不创建 Worker。

---

# 10. Task terminal

Task terminal 后：

```text
no new ask/reply
no pending collaboration browser delivery
no node wake
```

已有 Collaboration Message **原样作为历史保留**，不新增 `CANCELLED/TASK_TERMINAL` 状态。

消息不能恢复或阻塞 Task terminal。

---

# 11. Gateway / Tunnel failure

```text
Custom GPT → public tunnel → Gateway
```

故障：

```text
Tunnel down
Gateway down
URL changed
network failure
```

规则：

- HTTP/transport failure 不自动等于业务成功；
- 重试同一业务调用必须复用 idempotency semantics；
- 只 Gateway 允许公网 exposure；
- Agent Runtime/Task/Execution/Browser bridge 不直接公网暴露。

Dev Tunnel Module 负责自身 install/setup/status/start/stop 闭环；account/login/public URL 等真实外部步骤进入 setup，深度 verification/diagnostic 可作为 package-owned extra capability。

# 12. New Task / Carrier identity 失败

Task先于Worker存在，因此任何Conversation identity失败都不允许通过“猜c-id”继续binding。

```text
Task(PENDING) exists
→ CREATE/open target Role Conversation
→ Browser observe current c-id / locator
→ Agent validate expected roleRef/packageName
→ bindTaskWorker
```

若无法可靠得到current Conversation identity：

```text
keep Task PENDING
→ mark/make missing binding observable
→ retry only missing Worker after fresh page reality
```

不得：

```text
invent c-id
reuse previous Task worker
bind tabId/frameId
让Product GPT自己createTask来绕过Carrier identity
```

Action本身不暴露stable Conversation c-id；Browser observation是v1正式边界。

# 13. SemVer / Web sync

Agent Package：

```text
patch = prompts/text correction, no role/API semantic break
minor = compatible capability/Action addition；future Knowledge specialization启用后，其兼容增补也可属于minor
major = incompatible role responsibility/Action/Carrier contract change
```

Package upgrade 不自动更新 GPT Web。

CLI：

```text
compare registeredPackageVersion
→ tell user which v1 Web fields/schema/capabilities need manual sync
→ future Knowledge启用时再追加Knowledge sync提示
→ user confirms sync
→ update local registered package version
```

v1 Agent 不自动写永久 memory。

# 14. 七包标准管理面验收

独立：

```text
agent-runtime
agent-gateway
browser-extension
dev-tunnel
agent-product
agent-controller-dev
agent-test-ops
```

每包必须统一提供 `install/uninstall/status/setup/docs/start/stop`，并由同一 Module-owned truth 实现。deterministic preparation 进入 install；人工/外部步骤进入 setup；无独立 runtime 时 start/stop no-op 且 `runtimeStatus=NOT_APPLICABLE`。

`custom-gpt/role/verify/doctor` 等 package-specific extra capability 可以存在，但 Platform Deployment 不代理、不解释。Platform 只按统一 protocol 编排/透传并汇总七标准能力。

# 15. 端到端 Happy Path

```text
A. J0 Role Ready
→ Gateway/Runtime/Dev Tunnel/Browser Extension ready
→ create/configure 3 generic Custom GPT Roles
→ register each roleRef
→ one random role credential each
→ Actions/Auth/File Bridge/Code Interpreter/Web Search requirements verified
→ routine Action permission configured for Always Allow target

B. J1 New Task
→ Extension createTask(PENDING)
→ CREATE/observe/bind Product + Dev + Test new Conversations
→ Product bound → immediately discuss Requirement
→ Dev/Test WORKER_BIND only + IDLE
→ partial failure retries only missing Worker
→ Product writes formal Task Requirement
→ deterministic readiness → READY

C. J2 Start
→ Extension human confirmation
→ startTask
→ first Node READY

D. J3 Wake
→ Task Observer reads drive projection
→ Carrier RESTORE correct workerRef/conversationLocator
→ minimal NODE_READY wake delivered
→ Worker calls formal startNode

E. J4 Worker Turn
→ use Conversation context / native file search
→ get fresh Task facts on demand
→ File Bridge / Code Interpreter / Web Search as needed
→ 0..N Actions in one Turn
→ Execution real Effect / Artifact / Result / Evidence
→ askPeer/replyPeer if needed

F. J5 Async / Reopen / Recovery
→ long Execution/Approval/Peer result ready
→ Task Observer wakes same Worker
→ true workflow blocker only uses Task WAIT
→ test failure → formal reopen → same Dev workerRef/Conversation, runNo+1
→ transport/Carrier failure uses Recovery, not Reopen

G. J6 Terminal
→ Task terminal
→ Task Observer stop-driving
→ bindings/conversation locator/collaboration/artifacts/evidence/logs retained
→ no ghost wake/new collaboration work
```

Browser不在每Action之间WAKE，不解析GPT自然语言作为Task truth。

# 18. STOP 门

出现以下任一情况先回架构/Owner：

```text
Task and Agent both become role→worker truth
Message Center creates Worker
different Task reuses same Worker Conversation
Extension infers Task state itself
Gateway directly reads another domain DB or executes tools
logical delete/tombstone is reintroduced in v1
reply durable alone opens next question
Task terminal is reopened by collaboration
public tunnel exposes Task/Execution/Runtime directly
Role Key is reused as Browser Extension identity
package lifecycle details are duplicated inside Platform Deployment
need WorkItem/Claim/Redis/Kafka/dynamic Capability Catalog to make v1 work
```

## 当前正式约束：恢复与真实 Carrier E2E

- Browser/Execution restart 后的 Conversation reality check 属于 Execution；Agent 只恢复 Role/Worker/Collaboration 持久事实。
- Collaboration delivery 采用可能重复调用 + idempotent/effectively-once；effect_started 后不确定必须由 Execution reality verification，禁止 blind resubmit。
- Carrier 行为必须真实 ChatGPT Web E2E；OpenAI 新能力按 VERIFIED/PENDING_SPIKE/REJECTED_OR_UNSUPPORTED 记录。

# 19. OpenAI Carrier File / Action Transport Failure

File Bridge 不改变领域 failure ownership，但增加以下明确恢复规则：

```text
input download_link expired / fetch timeout
→ 不持久化旧 URL
→ 先查询 owning Domain 最新 facts + 既有 idempotency/action/execution result
→ 由 Worker 取得/提交 fresh transient `openaiFileIdRefs`；只重试尚未产生 business mutation 的 fetch/materialization transport
→ 若原 Action 可能已经产生业务写入，必须先按原 idempotencyKey/fingerprint 查询结果，禁止 blind replay 整个 business Action
→ 不盲用旧 bytes

output relay fetch failed
→ TaskDocument / Execution Artifact 继续作为 canonical source of truth
→ 重新生成短期 relay
→ 不复制业务文件成为 Gateway-owned durable storage

Action 45s ceiling
→ 返回 accepted/ref 或明确错误
→ 后续查询/Worker continuation
→ 不让 Gateway 隐藏为长期 hanging request
```

Action auth、GPT Web schema、Role capability 失配属于 Carrier/Deployment problem；Execution 真实 Effect 已开始时仍按 Execution UNKNOWN/reality verification 处理，不能因为 Carrier request timeout 就重做 Effect。

`x-openai-isConsequential:false` + Always Allow 已是v1 happy-path设计；在最终目标环境proof完成前，仍必须保留unexpected permission prompt现场与continuation作为异常恢复证据。无论proof状态如何，都不得恢复成每个routine Action由Browser机械点击permission的主链。

# 20. Observer / Decision Authority 验收

- Task Observer正常progression必须deterministic；只有单Task conflicting facts/UNKNOWN/repeated recovery/unexplained stall才请求REASON diagnostic。
- System Observer只做whole-system bounded assessment：8类views→concern batching→carry-forward→drill-down→global synthesis；模型busy/unavailable只defer。
- Owner fact/Hard Rule > deterministic > FAST > REASON > Human authorization；模型confidence不覆盖DENY/REQUIRE_APPROVAL/version/idempotency。
- FAST/REASON/Vision不是第四Worker；System Observer不是System Administrator。
