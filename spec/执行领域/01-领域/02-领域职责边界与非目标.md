# 01 · Execution Domain 领域职责、边界与非目标

## 1. [FROZEN] 领域所有权

Execution 拥有：

- 真实执行意图的受控落地；
- Execution Record；
- Execution Scope / Policy enforcement；
- Effect Approval 语义；
- Executor routing；
- Result / Evidence；
- UNKNOWN_SIDE_EFFECT 与恢复原则；
- Execution 日志关联；
- Browser/Local executor 真实执行协议。

Execution 不拥有：

- Task 的任务状态、Node 状态、Plan、TaskDocument、worker binding 真源；
- Agent 的 Role、Worker、Agent Package、Collaboration Message Center；
- Model Runtime 的模型加载、active model、推理服务生命周期；
- Deployment 的 package/Module install/uninstall、status/setup/docs/start/stop 与 External Resource 治理；
- 产品知识库内容和授权业务语义。

## 2. 跨域边界

### Task & Orchestration

Task 是流程真源。Execution 只能通过 Task Public API 校验当前 Task/Node/run/worker binding/context，不得直读 Task SQLite。

执行成功并不自动等于 Node 完成；Node 完成必须通过 Task Domain 自己的正式 transition。

### Agent Runtime & Collaboration

Agent 是 Role/Worker/Collaboration 真源。

Browser Extension 虽然物理操作 ChatGPT 页面，但不能因此拥有 Role/Worker 业务对象；`roleRef + workerRef` 是稳定业务身份，Tab 只是临时载体。

Gateway 归 Agent Domain；Gateway 只做公网入口、认证、路由、协议转换，不执行 File/Shell/Browser。

### Model & Inference

Execution 请求 FAST / REASON / Vision judgement，但不拥有模型服务的 active model、队列、加载、推理实现。

模型判断是 Execution Policy 的一个信号，不是 hard rule 的替代品。

### Deployment

Deployment 只负责 Execution 相关 Module 的 package install/uninstall 与 `Module.install/status/setup/docs/start/stop` 标准管理接缝；真实 Execution verification/diagnostic 若需要，仍由 owning Module 作为自身能力提供。Deployment 不拥有 Execution Record/Policy/Capability 语义。

## 3. Task Start Confirmation vs Effect Approval

v1 不存在由 Task Domain 持久化的独立 `Task Approval` 事实。用户在 Extension（未来可替换为 Feishu）执行“批准并开始”只是 human interaction channel；Task 重新校验 readiness/version/idempotency 后执行正式 `startTask`。

Effect Approval 才是正式安全事实：是否允许当前具体危险副作用发生，由 Execution 持有 executionRef/effect fingerprint/scope/actor/expiry 等有效性语义。

二者必须分离：Task start confirmation 绝不能被解释成后续所有危险 Effect 永久授权；ChatGPT Always Allow/permission 也不等于 Execution Approval。

## 4. [REMOVED / DEFERRED]

- MCP：v1 删除。
- Knowledge Retrieval：只留未来扩展位。
- Remote Execution：未来需求再做。
- Docker/K8s：不进入 v1 Execution。
- Logging/Observability：不是独立领域。

## 5. 不允许的隐性越界

以下都属于实现错误：

```text
execution-local 直接更新 Task status
browser extension 把 tabId 当 workerId
execution-runtime 直接读取 Agent SQLite
Gateway 直接 spawn shell
Model Runtime 直接操作文件
Task Service 直接操作 Chrome
Browser Extension 自己发明 Approval 业务状态
```

边界判断标准：**谁拥有业务事实，谁提供 Public API；Execution 只执行和验证现实。**

## 6. Artifact / Observer boundary

- `ArtifactRef` 是 Execution-owned materialized bytes/output identity；`EvidenceRef` 是证明 Result/Delivery/Effect 的证据 identity；TaskDocument/Conversation file/File Bridge locator 不取代二者。
- Task Observer/System Observer 可以消费 Execution public facts；正常 Task progression不通过 Model/Observer修改 Execution。
- System Observer 的 assessment/recommendation 不是 Execution policy result；model confidence 永远不能覆盖 hard DENY/REQUIRE_APPROVAL/scope/identity/idempotency。
