# 12 · 测试、验收、E2E 与故障注入

## 1. Gate E1 — Contract / Policy / Ownership

必须自动证明：runtime validation、Capability/Result/Error union、Execution state transition、idempotency/fingerprint、scope/redaction、Policy hard rule、Approval owner、UNKNOWN no-blind-replay。

跨域额外证明：

```text
Task start confirmation ≠ Execution Approval
ChatGPT Action permission ≠ Execution Approval
System/Task Observer recommendation ≠ Execution decision
model confidence < Policy hard rule
```

## 2. Gate E2 — Local Real Execution

真实临时Git项目验证file/git/package/test/process/network/shell等typed capabilities，含path/symlink/.proflow/secret/environment/timeout/cancel安全边界与lost-response reality recovery。

## 3. Gate E3 — Real Browser Carrier

必须真实 Chrome + ChatGPT Web，覆盖J1/J3/J4中Browser-owned reality：

```text
CREATE Product/Dev/Test Conversation
observe c-id / conversationLocator
partial CREATE recovery
RESTORE existing Worker
minimal WAKE
programmatic DOM input/submit/observe
Always Allow routine path（无每次Browser click）
unexpected permission prompt recovery
Collaboration physical delivery
screenshot → Vision fallback
```

明确反向测试：

```text
no frame registry / frame handshake / iframe workspace
no persistent tab business identity
no Browser natural-language Task completion
no ordinary file DOM upload/download main path
no action-level Browser “continue” scheduler
```

## 4. Gate E4 — Reliability / UNKNOWN

至少破坏：Extension reload、navigation、Chrome restart、runtime↔extension disconnect、submit前/后断线、result/reply lost、stale content instance。

验收：

- existing Worker不duplicate CREATE；
- `workerRef/conversationLocator`恢复后重新定位page；
- submit后不确定先same Conversation observe；
- confirmed absent才retry；confirmed delivered复用；still uncertain→UNKNOWN；
- Execution effect_started后同样reality-first；
- terminal Task no business WAKE；
-技术recovery不改成Task reopen。

## 5. Gate E5 — Cross-domain J0→J6

```text
Role READY
→ Extension createTask(PENDING)+3 Worker binding
→ Product Requirement
→ READY + human confirmation → startTask
→ Task Observer RESTORE/WAKE
→ Worker startNode
→ one Worker Turn / 0..N Actions
→ File Bridge / CI / Web Search（按需）
→ Execution Effect / Artifact / Result / Evidence
→ Collaboration async wake（按需）
→ complete / true wait / reopen same Worker runNo+1
→ terminal / no ghost wake
```

Execution只证明real effect plane；Task progression必须由Task owner command产生。

## 6. Observer / Model 联合 Gate

### Task Observer

正常READY/RESULT/REPLY/REOPEN deterministic，不调用模型；单Task conflicting facts/UNKNOWN/repeated recovery/unexplained stall才REASON diagnostic，且结果不能直接effect/transition。

### System Observer

8类bounded views→concern batches→carry-forward→drill-down→global synthesis。System Observer最低优先级，phone model busy/unavailable只defer assessment。

Execution向Observer提供bounded status/result/evidence summary；不允许Observer写Execution status/sideEffectState。

## 7. File Bridge / Artifact Gate

- inbound refs由Gateway normalize、Execution bounded materialize/hash/MIME/size；
- Context Pack/Patch是Execution Artifact subtype；
- GPT proposal artifact不等于effect applied；
- platform→GPT image不依赖ordinary file response，screenshot/Vision路径保留；
- transport retry与business mutation replay分离。

## 8. Evidence

推荐输出：structured test result、Execution records、Result/Evidence/Artifact refs、Carrier operation result、necessary screenshots、Observer assessment refs、structured logs。失败必须能从executionRef/operationRef下钻。

## 9. STOP

若实现需要frame topology、Browser第二Effect Store、Observer direct mutation、model override Policy、把Always Allow当Execution授权、或用GPT自然语言代替owner fact，立即STOP。
