# 任务与编排领域｜上下文继承与跨领域边界

## 1. Task 是长期工作事实真源

Task Domain 只保存流程和长期业务事实，不拥有具体 Agent Carrier、Browser 页面现实、Model Runtime 或 Deployment lifecycle。

## 2. 与 Agent Domain

Task 持有 `TaskRoleBinding(agentPackageRef, roleRef, workerRef, conversationLocator)`，但把 Agent/Carrier refs 当 opaque：不解析 g-id/c-id/URL 格式、不读取 Role Registry、不拥有 Conversation lifecycle。Node 逻辑岗位要求使用 `requiredAgentPackageRef`，不使用真实 g-id 作为 role type。

```text
Agent owns: Role / Worker identity / logical collaboration
Task owns: TaskRoleBinding / Node / workflow
```

Extension 先创建 PENDING Task，并声明固定三个 `agentPackageRef + roleRef` participant；随后 Browser Carrier 并发创建/识别 Product/Dev/Test Conversation，通过 Task Public Contract one-time 绑定 `workerRef + conversationLocator`。Product 不再在 Task 创建前持有特殊 pre-Task Worker。

## 3. 与 Direct Tools / Execution

```text
Task owns: what work should progress
Direct Tools: Repomix / Local Dev / CodeGraph 的本地工程调用与 Provider result
Execution owns: Browser/Carrier 等需要 durable side-effect recovery 的内部 effect/evidence
```

Direct Tool result 不属于 Task truth，也不自动推进 Node；Agent 判断工作完成后显式调用 Task Public Command。Tool request 不依赖 Task/Node/Worker identity。

Browser CREATE/RESTORE/WAKE、permission、screenshot、submit、delivery、recovery 继续属于 Execution/Carrier。Browser 不直接写 Task Store；任何 Task 状态推进都必须调用 Task Public Command。

Business `WAITING/FAILED/TERMINATED` 与 Tool `TOOL_RESULT_UNKNOWN`、Execution `UNKNOWN_SIDE_EFFECT` 是不同状态空间；技术不确定性不得被映射成 Task 自动重试。

## 4. 与 Model Domain

Task 可以通过公开推理合同请求认知结果，但 Model 不反向读取 Task DB；Task/调用方组装必要 context。模型输出不是 Task 状态变更授权。

## 5. 与 Deployment Domain

Deployment 只负责 Task 相关 Module 的 package install/uninstall 与 `Module.install/status/setup/docs/start/stop` 标准管理接缝；Task migration 等真实额外能力仍由 owning Module 自己提供。Deployment 不拥有 Task state machine、Store 业务语义或 TaskDocument 内容。

## 6. 与 platform-host

`platform-host` 只做 composition root、依赖注入、本地 transport 和轻量 health aggregation。Task package 不依赖 platform-host；platform-host 依赖并装配 Task package。

## 7. ref 与数据边界

- 跨域只传 Public Contract 中定义的 opaque ref 与 DTO。
- 禁止共享 SQLite 表、Repository、内部 Adapter 或 deep import。
- 任何跨域 mutable fact 只有一个 owner；其他领域只能缓存可丢弃 projection，不能形成第二真源。

## 8. 失败隔离

Agent/Execution/Model/Deployment 依赖失败必须通过 typed error / status 显式返回；Task 只根据自己拥有的业务语义决定 WAITING、FAILED、继续或恢复，不能借依赖失败私自改写其他领域状态。


## 8. 与 Task Observer / Reconciliation / System Observer

Task Observer 的 deterministic decision 与 lost-trigger reconciliation 属 backend application logic，只读取 Task Public Query 与其他 Owner durable/current facts 后发 typed WAKE/RESUME request；不写 Task。事件、页面变化、reconnect 仅作 kick，bounded catch-up 保证丢 hint 后最终重新发现 READY。普通 Direct Tool result 不进入 Observer progression 条件；Agent 自己决定何时 complete/wait/fail/reopen。

正常 READY/REPLY 不调用模型。单 Task 异常诊断可调用 REASON，但输出不能直接改变 Task；System Observer 处理跨 Task/系统趋势，并与 progression single-flight 隔离。详见 `TASK-DOC-03-05` 与 `PLATFORM-DOC-01-04`。
