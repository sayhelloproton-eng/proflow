# 01｜领域边界与依赖约定

> 状态：FROZEN  
> 目标：确定五个正式领域如何拥有事实、通过 Public Contract 建立依赖，以及 platform-host / Extension / Gateway / Observer 等 Application/Adapter 如何组合而不成为新的业务 Owner。

---

# 1. 第一原则：一个可变业务事实只有一个 Owner

```text
Task / Node / runNo / TaskDocument / TaskRoleBinding
→ Task & Orchestration

Role deployment / roleRef / credential / Worker identity / Collaboration message
→ Agent Runtime & Collaboration

Execution intent / Effect / Result / Evidence / dangerous-effect Approval
→ Execution

ReasoningSpec / FAST / REASON / Vision / provider capability & health
→ Model & Reasoning

Module Governance / package lifecycle / standard install-uninstall-status-setup-docs-start-stop contract
→ Deployment
```

Browser、Observer、日志、Conversation 都不得成为第二真源。

---

# 2. 身份跨域使用，但 ownership 不转移

Task Worker Binding 第一版使用：

```text
agentPackageRef / packageName  = 逻辑泛化岗位
roleRef                        = 已部署 Custom GPT identity
workerRef                      = Task-scoped Worker / Conversation c-id
conversationLocator            = Carrier 恢复地址
```

Task 可以持久化 binding fact，但 Agent/Carrier 仍拥有 identity 的外部语义与验证；Task 永远不保存 `tabId/frameId/windowId`。

credential 只用于 GPT→Gateway 认证，Browser 不持有、不验证 credential；credential 不能等于公开 packageName。

---

# 3. Public / Internal 边界

跨领域依赖只能指向 Public API/Port/Contract/Event/Query/typed Result。禁止 deep import、共享 Repository/ORM/SQLite table。

Provides/Requires 是依赖真源，必须指明 Provider 与具体 Contract，不能写模糊“需要某领域数据”。

---

# 4. Application Composition 允许组合，但不能拥有领域状态

允许：

```text
platform-host
agent-gateway
Extension application/background
Task Observer
System Observer
```

组合多个 Public Contract。

但 Application/Adapter：

```text
MUST NOT 拥有 Domain state machine
MUST NOT 直接写 Owner DB
MUST NOT 从日志/DOM/Conversation 推导并覆盖业务事实
MUST NOT 为跨域方便创建第二套 durable truth
```

---

# 5. platform-host 不是第六领域

`@tomflow/proflow-platform-host` 只负责本地 composition、DI、transport、startup/shutdown、light health aggregation。它可以装配 Task/Agent package 与 Execution/Model public clients，但不拥有 Observer 的业务判断、不拥有 Browser page runtime，也不持久化跨域 mirror。

Extension 中的 Task Observer/System Observer/Carrier Controller 是 application logic；platform-host 只提供其需要的 owner public transport/client composition。

---

# 6. Task Observer 与 System Observer 的边界

## Task Observer

```text
scope = one concrete Task
logic = deterministic progression first
output = typed wake/resume/recovery request
```

正常 READY/Execution Result READY/Peer Reply READY/Reopen READY 不调用模型。单 Task ambiguity 可调用 REASON diagnostics，但无 workflow authority。

## System Observer

```text
scope = whole ProFlow system
logic = bounded snapshots + low-priority REASON assessment
output = derived assessment / finding / recommendation / drill-down request
```

它不成为统一 Scheduler，不拥有 Task/Execution/Agent/Deployment facts。

---

# 7. 决策权层级

平台横切优先级：

```text
Owner current fact / Hard Rule
>
Deterministic Logic
>
FAST（普通语义判断）
>
REASON（复杂歧义/归因）
>
Human（授权或最终不可消歧判断）
```

模型置信度不能覆盖 DENY、REQUIRE_APPROVAL、scope/identity/version/idempotency rules。

GPT Worker 与 FAST/REASON/Vision/System Observer 不同：手机模型不是第四个 Worker，也不成为 Controller Agent。

---

# 8. Custom GPT Native 能力的领域位置

Custom GPT Conversation、File Bridge、Code Interpreter、Web Search、Multi-action continuation 属于 Carrier/Worker 可复用能力，不新增 ProFlow Domain。

```text
需要知识/分析 → GPT Native 优先
读取/改变正式 ProFlow fact → Action → Owner Domain
改变真实机器/外部现实 → Execution
跨 Worker 认知沟通 → Collaboration
```

File Bridge 是 transport；TaskDocument/Artifact/Evidence 仍分别归 Owner。

---

# 9. Browser Carrier 必须保持薄

Browser Extension 属于 Execution delivery/carrier 单元，负责 Conversation create/open/restore/WAKE/submit/observe/screenshot/recovery。

第一版明确不需要：

```text
Frame Registry
frame-role handshake
iframe team workspace
persistent tab business identity
Browser Task/Message/Artifact Store
DOM 自然语言 business result parsing
```

`tabId` 只允许作为 transient diagnostic/runtime address。

---

# 10. Async owner facts 不自动改变 Task workflow

Execution RUNNING/WAITING_APPROVAL、Collaboration PENDING、Carrier recovery、Model assessment deferred 继续属于各 Owner。结果 ready 后由 Task Observer重新唤醒 Worker。

只有 Worker 正式声明真实 workflow blocker 时才使用 Task WAIT 语义。

---

# 11. Recovery 必须 reality-first

任何可能产生真实 Effect 的步骤：

```text
confirmed absent → safe retry
confirmed applied → reuse result
uncertain → observe current reality
still unknowable → UNKNOWN, no blind replay
```

Reopen 是业务返工；Recovery 是技术恢复。技术 failure 不得偷偷改成 Task reopen。

---

# 12. 禁止共享数据库作为集成接口

即使同进程、同机、同 SQLite 文件，逻辑 ownership 仍独立。跨域只通过 Public Contract 和 opaque refs。
