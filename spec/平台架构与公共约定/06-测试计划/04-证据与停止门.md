# 测试证据与停止门

## 1. Evidence 分级

```text
Implemented
Contract Verified
Domain/Module Verified
Integrated
E2E Verified
Real Environment Verified
Production Hardened
```

禁止 Unit PASS → Production Ready。

## 2. 三类记录严格分开

```text
Business Fact = Owner truth
Evidence      = real effect/result/delivery proof
Log           = diagnostic trail
```

System Assessment 是 derived artifact，不是Business Fact。

## 3. 必须可观测的 Evidence

至少包括：

- schema/contract validation；
- Task/Node/Binding owner state ref；
- Carrier create/restore/wake physical result；
- Execution Record/Result/Evidence/UNKNOWN reconciliation；
- Collaboration message/reply/delivery receipt；
- File Bridge materialization/relay metadata；
- Model Task Diagnostic/System Assessment structured result；
- System Observer batch/carry-forward/drill-down trace；
- Deployment verify/current reality；
- real Chrome/Custom GPT observation where required。

## 4. 全局 STOP

- Public Contract不一致；
- unknown effect没有reality verification；
- 为绿灯需要改Frozen Owner/State/Contract；
- Observer需要direct business mutation；
- Browser需要frame/persistent tab/business store；
- model confidence要覆盖Policy；
- current code被用来反向修改规范；
-真实外部能力只能Mock自证；
- flaky critical proof靠无限rerun；
- historical evidence被改写以“证明”新架构。

## 5. SPEC_GAP

`SPEC_GAP` 是规范缺口，不是允许实现自行补设计。阻断正确实现时 STOP→正式Design/Contract Change；不阻断则标记PENDING_DECISION/PENDING_SPIKE与fallback。
