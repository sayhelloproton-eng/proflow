## 5. 本 Chat 的主要效率教训

1. `READY_FOR_REAL_3` 判早：真实 Task→Observer→MV3 SW→bridge→wake→Conversation→Execution 首次完整串联事实上发生在所谓“最终验收”里。
2. 只修 FIRST bug 后立即发布，导致 patch train；Codex 只能缩短单个 loop，不能弥补 loop 数量失控。
3. Browser adoption 假阳性曾让新代码排障实际运行在旧 0.1.45 runtime 上，污染整棵故障树。
4. `VALID_DEFECT != CURRENT_ROOT_CAUSE`；真实 defect 没有 causal closure 不得吸入当前 Real Gate。
5. Browser privileged UI 与 release harness 的机械噪音曾消耗明显时间；canonical path/authority readback 必须优先。
6. 文档与正式 closeout 频率过密也切碎了主线；Real Gate 中只维护 CURRENT，稳定后再一次性沉淀。

## 6. 新执行模型

