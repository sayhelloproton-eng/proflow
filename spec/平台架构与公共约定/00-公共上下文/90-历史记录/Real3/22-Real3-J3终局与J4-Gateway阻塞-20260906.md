## 6. J4 Agent Gateway root cause

运行态分层 readback：

```text
Agent Gateway /health = 200 UP
Agent Gateway /ready = 503
  credentialStore=true
  downstream=false
  ingress=true
  relay=true

Platform Host /ready = 200 READY
  task=READY
  agent=READY
  execution=READY
  model=READY
```

Code/current-source 证明正式 action 路径：`createAgentGatewayProcess → createAgentGateway → handler → AbortSignal.timeout(options.actionTimeoutMs) → owners.route`。

确定性 mismatch：

```text
GatewayOptions.actionTimeoutMs = optional
createAgentGatewayProcess() = 未传 actionTimeoutMs
handler = 无条件 AbortSignal.timeout(options.actionTimeoutMs)
Node 24 mechanical repro:
AbortSignal.timeout(undefined)
→ TypeError ERR_INVALID_ARG_TYPE
handler catch
→ HTTP 500 {"error":"GATEWAY_FAILURE"}
```

因此 J4 的 `GATEWAY_FAILURE` 发生在真正 downstream `owners.route()` 之前；不是 package.json 文件不存在，也不是 Execution/Model/Task Owner 不 READY。该 root cause 已机械确认，但源码修复尚未开始。

邻接的 Gateway `/ready downstream=false` 仍只记录为独立诊断现象。readiness probe 使用 2 秒 downstream `/ready` budget，当前没有证据要求与 action-timeout root cause 合并修复。
