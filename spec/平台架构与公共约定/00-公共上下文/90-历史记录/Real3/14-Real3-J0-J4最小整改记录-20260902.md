## 3. R3-B01｜Browser 真提交判定

最小变更：

- 新增 `containsSubmittedFingerprint`；只承认 `data-message-author-role="user"` 的已发送消息节点。
- 输入框、assistant 文本、页面其他残留文本不能证明 delivery。
- Browser Bridge `SUBMIT` 返回前做 bounded sent-message verification；超时为 `MESSAGE_SUBMIT_REALITY_UNCONFIRMED`。
- `worker.create` 与 `worker.wake` 都要求 `hasMessage=true`；CREATE 消息未确认时不持久化 TaskRoleBinding。
- 不增加 blind replay；真实 Effect 已开始后的不确定继续交给 Execution `UNKNOWN_SIDE_EFFECT` 语义。

根 Owner：`execution-browser-extension`。

## 4. R3-B02｜Worker-only startNode

最小变更：

- Task Owner `startNode` 按 `requiredAgentPackageRef` 取 TaskRoleBinding 后，强制校验 `actorRef == worker:<binding.workerRef>`。
- 错误 Worker / Observer actor 返回 `WORKER_MISMATCH`，Task/Node 版本和状态保持不变。
- Platform Host 区分传给 Task command 的 `worker:<workerRef>` actor 与传给 Execution scope 的原始 `workerRef`，不改变公开 Action 输入。
- `PlatformHostTaskDriverPorts` 删除 `startTask/startNode` 写能力和 `platform-host:task-observer` actor 注入路径。
- 保留 Observer 所需的 bounded read projection；Extension Task Application 和 Worker 正式 Owner API 主链不变。

根 Owner：`task-orchestration` + `platform-host`。

## 6. R3-B03 / R3-B04｜WAKE 成功语义与 bounded recovery

继续沿 J3 调用链复核发现：

- Platform Host 的 `task.wake` 原先直接返回 Execution record；即使 record 为 `FAILED / NOT_APPLIED` 或 `UNKNOWN`，HTTP 仍为 200。
- Browser Observer 只按 HTTP 状态判断 `invokeObserverApplication` 成功，因此会把未确认的 WAKE 记录成 `SUCCEEDED`。
- startup/event recovery 对 `taskObserver.drive` 和 `task.ensureWorkers` 的失败直接吞掉；`task.list` 成功时不会安排下一次 bounded pass，瞬时失败可能使 READY Node 停住直至另一个外部事件发生。

最小变更：

- Host `task.wake` 只有在 Execution record 同时为 `status=SUCCEEDED`、`sideEffectState=APPLIED` 时返回 200；其他状态返回 `TASK_WAKE_NOT_CONFIRMED:<status>:<sideEffectState>`。
- Extension recovery 对未确认 WAKE、未确认 Worker recovery、未消费的 durable signal 设置 retry 标记，最多 6 次、间隔 2 秒。
- retry 继续使用原有稳定 Execution idempotency identity；不在 Background 直接调用 `executeCapability`，不绕过 Execution 对 `APPLIED / NOT_APPLIED / UNKNOWN` 的 no-blind-replay 裁决。

根 Owner：`platform-host` 应用边界 + `execution-browser-extension` bounded recovery lifecycle。
