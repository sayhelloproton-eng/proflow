## 4. 0.1.31 发布事故与 0.1.32 纠正

本 Chat 发布 `dev-tunnel@0.1.31` 时错误使用了裸 `npm publish`，绕过 pnpm workspace publish transform。Registry 0.1.31 authority readback：

```text
@tomflow/proflow-module-contract = workspace:^
@tomflow/proflow-deployment-conformance = workspace:^
```

因此 Product Workspace 单包 update 触发 `EUNSUPPORTEDPROTOCOL workspace:^`。这不是业务代码缺陷，而是**错误 publisher 造成的坏发布物**。

Repomix 扩到最小 release tooling 后确认仓库正确 publisher 最终使用：

```text
pnpm publish -r --no-git-checks --filter <package>
```

pnpm tarball authority check 证明该路径会把 `workspace:^` 正确转换为真实 semver。随后 metadata-only 推进到 0.1.32，并使用正确 pnpm workspace publisher 发布。
