# 工作区重新部署手册

> Owner：candidate 形成后的真实 Deployment / Adoption。
> 唯一正式 Product Workspace：`/Users/agent/Desktop/proton-workspace`。
> 本文只负责“怎么部署”；测试场景与证据细节看 `02`，环境当前状态看 `04`。

## 1. 前置门

只有 `02` Step 1～10 全 PASS 才进入：

- frozen source SHA / lock hash；
- changed packages 已发布并 Registry exact/integrity 回读；
- 三 Provider contract + real smoke 已 PASS；
- 三 Role OpenAPI/provisioning Gate 已 PASS；
- 无源码漂移。

## 2. 是否 Fresh

“重新部署”默认不等于 Fresh。

### 保留 Workspace state

直接在真实目录跑完整 install/setup/start，保留 `.proflow` 历史数据。适合验证升级/采用。

### 从零用户验收

只有明确要验证全新 Workspace 时才执行：

```bash
cd /Users/agent/Desktop/proton-workspace/repos/proflow
pnpm fresh:workspace --workspace /Users/agent/Desktop/proton-workspace
```

它会清 `.proflow`、node_modules、package manifest/locks/releases；因此一旦 Fresh，旧 Task/Worker/Conversation 不再是验收前提。执行前必须记录当前 authority snapshot。

## 3. 正式部署顺序

如 `platform-cli` 本身有新版本，先安装 frozen candidate 对应的真实 Registry exact 版本，然后：

```bash
platform install --workspace /Users/agent/Desktop/proton-workspace
platform status --workspace /Users/agent/Desktop/proton-workspace
platform docs --workspace /Users/agent/Desktop/proton-workspace
platform setup --workspace /Users/agent/Desktop/proton-workspace
platform status --workspace /Users/agent/Desktop/proton-workspace
platform start --workspace /Users/agent/Desktop/proton-workspace
platform status --workspace /Users/agent/Desktop/proton-workspace
```

`platform install` 是完整 governed package-set sync + Module.install，本轮最终部署不用逐包 `platform update` 冒充完整安装链。

## 4. Setup 重点

必须真实确认：

- Browser Extension actual loaded artifact/version；
- Dev Tunnel public ingress；
- 三 Tool Provider 配置与独立 readiness；
- 三个 Role GPT 的 Action schema/auth；
- 若 schema drift 不能原位更新，按正式 provisioning 显式 recreate + current Role replacement；
- Model/Execution 的可选/内部依赖状态不错误阻塞 Task/Peer/direct Tools。

OAuth/2FA/CAPTCHA/真实 secret 只在 owner 明确要求时交给用户；机器可完成的步骤不退回人工。

## 5. 部署后真实验证入口

默认创建**新的真实验证 Task + 新 Worker Conversations**，原因是本轮 Action schema 发生 breaking 变化；不能假设旧 Conversation 自动获得新 schema。

真实链：

```text
Extension New Task
→ Product Requirement / TaskDocument
→ start Task
→ Dev getTask/getNodeContext
→ Repomix + CodeGraph + Local Dev
→ 必要 Peer / putTaskDocument
→ completeNode
→ Test 自动被发现并 WAKE
→ Test 独立 Tools 验证
→ completeNode
→ Task terminal
```

工具调用体不得出现 Task/Node/Worker/Execution 身份字段；Host tool path 不得查询 Task 或调用 Execution。

## 6. 冷启动门

真实业务验证 PASS 后：

```bash
platform stop --workspace /Users/agent/Desktop/proton-workspace
platform start --workspace /Users/agent/Desktop/proton-workspace
platform status --workspace /Users/agent/Desktop/proton-workspace
```

不得 repeat start 创建第二套 runtime；不得无需求地 disable/enable Extension 或删除 GPT identity。

## 7. 失败恢复

- setup/install/start/publish UNKNOWN：先回 Registry/Module/runtime authority，不盲重试。
- 产品 defect：保存 FIRST_DIVERGENCE + candidate/runtime/Task evidence，退出 Final Gate，回 `02` 对应 Step 修复。
- Harness failure 单列，不直接判 Product FAIL。
- Final Gate 现场禁止源码 patch。
