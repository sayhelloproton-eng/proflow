### 9.1 效率规则

- **脚本优先**：重复、机械、确定的动作（workspace clean、Registry readback、状态采集、CLI 状态机、hygiene check）优先沉淀为安全脚本/harness，不反复用几十次 MCP 调用模拟手工。

- **实时反馈不允许反向制造碎片化执行**：一次跨文档批处理、一次状态采集批次、一次 harness 执行都各算一个“有意义步骤”；只在该批次结果成立后反馈一次，不按底层 tool call 数量刷屏。

- **正常路径低采样，异常路径高采样**：Playwright Chrome 是“眼睛”，但不机械每一步截图；关键浏览器状态转换观察，异常时再增加截图/Console/Network 采样。
- **测试最后统一跑**：发现阶段不边找边全量 test；先冻结完整 root set、批量整改，再统一验证。
- **发布按整改批次，不按单 Bug**：一轮发现 → 一轮整改 → 一轮验证 → 一次版本/发布 → Fresh replay，避免 Registry 变成逐 Bug 日志。
