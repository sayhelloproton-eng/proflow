## 9. 工程纪律与 MCP 截图方法

### 9.1 一次只做一个领域

```text
一个领域
→ 独立审计
→ 最小整改
→ gate
→ checkpoint
→ commit
→ STOP / 汇报
```

当前优先级已调整为：

```text

再 Model Domain 最终收口与 main 窄吸收
最后全平台交叉审计与七命令人工链
```

不要扩到 Gateway、Agents、Execution Runtime 全域、J1 或最终 Fresh Workspace 总验收。

### 9.2 小批与 checkpoint

- 小批默认 2～4 文件；
- 接近 5 个文件或完成一个 root cause：`STOP → checkpoint → 汇报`；
- 排除 `.git`、`node_modules`、`dist`、`coverage`、cache 和临时产物；
- checkpoint 是保全，不等于 commit、PASS、push 或 release。

### 9.3 Format / Biome / gate

```text
pnpm format
→ pnpm exec biome check --write <changed files>
→ targeted tests
→ package tests
→ package typecheck
→ 必要 architecture / governance / manifest checks
→ git diff --check
```

`pnpm format` 不能替代 Biome organizeImports / safe fixes。Frozen 输入不得被 formatter 改写。

### 9.4 Chrome MCP 实时观察

```text
执行一个 CLI / setup 动作
→ Chrome MCP 读取页面并截图
→ 确认页面、选中状态和真实反馈
→ 回读 CLI / JSON / process / persistence 权威状态
→ 再进入下一动作
```

Dev Tunnel 必须观察 GitHub Auth 页面、授权后跳转、current public HTTPS URL、错误页/旧地址/404/连接失败及 rerun 的非预期浏览器动作。

- 截图证明浏览器反馈；
- CLI/JSON/process/files 证明 auth、Tunnel、port、host 与 READY；
- 截图不替代 authoritative state，CLI 文本也不替代真实页面；
- 不可约授权由用户完成；截图确认后明确暂停，不擅自授权；
- 禁止 broad fuzzy click、连续盲点和长时间无反馈。

### 9.5 timeout / UNKNOWN

```text
timeout 或 UNKNOWN
→ 禁止 blind retry
→ 恢复 authoritative state
→ 判断 DELIVERED / ABSENT / UNKNOWN
→ 再决定下一步
```

适用于 publish、release、deploy、install、migration、外部创建和 Tunnel create/delete/host。
