# 公共上下文治理规则

> 目标：降低跨 Chat 接管成本，避免“知识存在但取不回来”。

## 四层所有权

- `01-长期规则`：铁律、总控、工具纪律、冻结边界。低频变化。
- `02-当前接力`：唯一当前事实入口。高频滚动覆盖。
- `03-自动化知识库`：包能力、基础动作、可组合流程。执行中持续优化。
- `90-历史记录`：旧 handoff、Round、已结束阶段、审计/整改原始记录。默认不加载。

公共上下文同时承担运行时控制面：读取只是入口，执行过程中必须把已经被机械证据证明的新状态和可复用知识写回唯一 owner。固定循环是：

```text
READ → ACT → OBSERVE → LEARN → WRITE BACK → CONTINUE
```

“当前 Chat 还记得”不能替代落盘；只要 Chat reality 已领先于 `CURRENT`，项目就已经发生 `CONTEXT_DRIFT`。

## 知识归属判断

```text
所有 Chat 都必须知道？ → 长期规则
下一 Chat 接着干必须知道？ → CURRENT
碰到某个包/外部资源就必须知道？ → 包能力 Runbook
多个流程都复用的机械动作？ → 基础动作
描述“先做 A 再做 B”的业务/验收编排？ → 流程
只用于追事故和过去证据？ → 历史记录
```

同一稳定知识只能有一个 owner。流程引用包 Runbook，不复制 Dev Tunnel / Browser / Model 的操作细节。

**高风险执行护栏允许“短句镜像”，但不允许多 owner。**例如 `Browser/UI 异常先看现实`、`UNKNOWN 禁止盲重试`、`截图就是眼睛` 这类一句话缺失就可能改变执行路径的规则，可以在 `README / 05-执行纪律 / CURRENT / owner Runbook` 同时出现；镜像只能复述同一语义并指向唯一 owner，不得在不同层新增条件、例外或另一套 SOP。完整方法仍只由 owner Runbook 维护。

模型吸收时禁止“重复即更高权重”的隐式投票。若镜像短句与 owner Runbook / CURRENT 的更具体语义不一致，先按 `长期硬边界 → CURRENT checkpoint → owner Runbook → 镜像 → 历史` 定位冲突；不要自行折中。冲突真实存在时停止执行并修正文档 owner，而不是让不同 Chat 各选一套解释。

## 每轮维护算法

执行前：`README → 长期规则 → CURRENT → REQUIRED_CONTEXT`。

执行中：Round 只记录真实 evidence、耗时、失败点、恢复 checkpoint；不要把聊天过程原样堆进 CURRENT。

执行后按写回矩阵归属：

| 新事实/经验 | 唯一写回位置 |
|---|---|
| 当前进度、版本、blocker、problem class、当前 tool route、第一 evidence、下一步、STOP POINT、禁止重做 | `02-当前接力/CURRENT.md` |
| 某个 Package / 外部资源以后都应这样操作 | `03-自动化知识库/包能力/<owner>.md` |
| 与具体包无关的提效、工具配合、恢复技巧 | `03-自动化知识库/基础动作/` |
| Deployment / Update / Real-N 的编排顺序变化 | `03-自动化知识库/流程/` |
| 单轮日志、PID、截图、耗时、事故原始 evidence | `90-历史记录/` |
| 所有未来 Chat 都必须遵守的新铁律 | 先经用户裁决，再进入 `01-长期规则/` |
| 产品 Owner / Contract / State / Test Plan 变化 | 正式领域 `spec/` / Test Plan，不写成公共上下文替代物 |

### Event Trigger｜关键事实变化立即写回

以下事件一旦由机械证据成立，**不得等到 Chat 结束或 Round 结束**；先按写回矩阵同步 owner，再进入下一重大动作：

```text
AUTHORITY_CHANGED        Git / Registry / Workspace / Browser / runtime 当前真值改变
CHECKPOINT_CHANGED       当前 Journey / Gate / STOP POINT 前进或回退
BLOCKER_CHANGED          旧 blocker CLOSED 或新 blocker 被确认
ROOT_CAUSE_CONFIRMED     第一处分叉 / owning root cause 已被机械证明
TOOL_ROUTE_CHANGED       最大不确定性跨 Plane，第一 authority / 工具路由改变
REUSABLE_LEARNING        新的包级、跨包执行知识被同场景验证
EXPENSIVE_FAILURE_LEARNED 高成本失败已形成明确的以后更短路径
```

未验证猜测不触发稳定知识写回；它只能留在当前诊断或历史 evidence。正式 Contract / Frozen Architecture 变化仍必须先由用户裁决。

### CURRENT Drift Guard

进入下一重大动作前快速检查：

```text
CURRENT_REALITY_DRIFT?
1. CURRENT 的版本 / authority 还是当前机械事实吗？
2. CURRENT_CHECKPOINT 还是当前真正 checkpoint 吗？
3. CURRENT_PROBLEM / blocker 还是当前最大不确定性吗？
4. NEXT_ACTION 第一项真的是马上要执行的动作吗？
```

任一答案为否：`SYNC CURRENT FIRST`。该检查不要求重跑昂贵验证，只读取已经存在的最新 authority；其目的只是阻止 Chat memory 与项目 memory 分叉。

### Round Closeout 六问

Event Trigger 是第一道即时同步；Round Closeout 是第二道漏项检查。每个有意义 Round 完成后，进入下一 Round 前必须回答：

1. `CURRENT` 是否变化？
2. 是否产生新的 Package / 外部资源稳定知识？
3. 是否产生可跨包复用的自动化/工具/恢复知识？
4. 当前 Flow 的顺序、checkpoint 或恢复路径是否变化？
5. 当前问题分类、第一 authority 或工具路由是否发生变化？
6. 是否存在只应进入历史的原始 evidence？

有变化就写回对应 owner；没有变化明确跳过。未验证猜测、重复命令输出、一次性 PID/截图不进入稳定知识库。只有所有六问完成，Round 才算 closeout。

## 防遗忘硬规则

CURRENT 遇到已知领域 blocker 时必须写 `REQUIRED_CONTEXT`；接手 Chat **先读对应 Runbook，再运行诊断命令**。`REQUIRED_CONTEXT` 只列固定 Core 读取完成后的**额外 active Runbook**：不得重复 `README / 长期规则 / CURRENT`，也不得把 `90-历史记录` handoff 当成必读上下文。确需追旧 evidence 时单列 `HISTORY_REFERENCES / ON_DEMAND_CONTEXT`，由当前问题触发后再读，避免历史叙事与当前 truth 同时进入模型注意力。

若 Runbook 已给出明确的 failure routing，禁止因换 Chat 重新探索已经裁决过的分支。只有新的真实证据与 Runbook 冲突时，才更新 Runbook。

历史记录不能作为当前 blocker 真源；当前机械事实晚于文档时，先机械确认，再更新 CURRENT。

### Chat 切换不再默认制造 handoff 文件

正常换 Chat 的唯一当前交接是 `CURRENT.md`，固定开场由 `01-长期规则/06-新Chat接管模板.md` 提供。治理成熟后不得再机械创建“当前Chat交接 + 下一个Chat提示词”成对文件。只有重大事故、独立审计、复杂 Round 原始 evidence、阶段终局等确需长期追溯的内容才进入 `90-历史记录`。

## 知识迁移硬门

归档/压缩旧上下文前，不允许只保留“原则摘要”就宣告治理完成。对每个会被新 Chat 真实执行的领域，必须检查以下五类可执行知识已经进入对应 Runbook：

```text
EXECUTION_ENTRY   = 从哪个公开命令/helper/tool 进入
CANONICAL_ASSET   = 已验证的唯一脚本/helper/公共 API
AUTHORITY_SOURCE  = 当前真值去哪里机械读取
RECOVERY_PATH     = 失败/UNKNOWN/断连后按什么顺序恢复
DO_NOT_REPEAT     = 哪些旧 transport/临时脚本/昂贵步骤禁止重新探索
```

任一项只存在于 `90-历史记录`、治理前快照或旧 handoff，而新 Runbook 没有承接，就视为 `CONTEXT_KNOWLEDGE_MIGRATION_GAP`，不能把该领域治理标 PASS。

治理完成后必须做一次“失忆新 Chat 执行模拟”：不给历史文件，只给 README/CURRENT/REQUIRED_CONTEXT，要求它说明**具体怎么执行和怎么恢复**，而不只是解释职责。如果答不出执行入口或 canonical helper，说明压缩过度，必须回历史提炼。
