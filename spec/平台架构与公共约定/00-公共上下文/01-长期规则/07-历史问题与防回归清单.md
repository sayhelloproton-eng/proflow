# 历史问题与防回归清单

这些不是待办，而是 Phase 3 已经付出过高成本的问题。后续 Chat 看到相似现象时先检查是否在重犯。

## 1. 无限扩散

症状：一个真实失败被扩成全仓审计、架构重新讨论、几十个抽象 residual。
规则：Real 阶段只定位当前 failure boundary；没有真实 evidence 不扩域。

## 2. 把 machine facts 交给用户

历史上曾暴露 `localBaseUrl/publicBaseUrl/stateRoot/databasePath/token/credential/bridge endpoint` 等内部事实。
规则：机器能产生、producer 能提供的事实必须自动流转；`ACTION_REQUIRED` 只留给真实人类/外部系统动作。

## 3. Platform 成为中间商

症状：Platform 理解 Module 私有配置、业务状态或硬编码 owner truth。
规则：Platform 只 discover/order/invoke/aggregate；Module 自己闭环。

## 4. 假 Fresh / 假 PASS

症状：复用旧 Workspace、local link、tarball 或只看 exit 0 就宣称 Registry/Real PASS。
规则：Registry/Fresh/real Journey 必须分别有真实 evidence；UNKNOWN 就是 UNKNOWN。

## 5. 长任务与盲重试

症状：publish/install 长时间无输出后直接重复执行，造成状态不可判定。
规则：先查询权威状态；长进程短启动 + poll；非幂等操作禁止盲重试。

## 6. 换 Chat 导致历史倒退

症状：新 Chat 不知道 CLOSED/PASS，重新开始旧整改。
规则：先读公共上下文；只有新 regression evidence 能重开旧阶段。

## 7. 用结构测试代替真实系统

单元/合同/全仓 gate 用来证明结构，不替代 Custom GPT、Browser、手机模型、Recovery 等真实外部行为。


## 8. 把验收总控退化成开发者 / 命令助手

症状：主 Chat 一看到失败就直接改代码、连续跑命令或跟随执行者节奏，反而没有先定义验收目标、分类失败、限定整改边界、作出 STOP/GO。

规则：验证总纲总控先主持验收；工程整改由当前可用的领域执行者或总控在用户授权范围内完成，不能把某个可选外部执行工具当成长期依赖。无论谁实现，修复后都必须回到原真实场景验收。

## 9. 用代码或 evidence 反向定义 Frozen Spec

症状：因为当前实现、测试或外部现象与规范不同，就把“当前现实”直接写成新的合同。

规则：规范真源与当前事实证据严格分开。实现不符规范 = implementation gap；外部现实证明规范假设不成立 = STOP → 正式 Spec/Contract/Design Change。不得静默回写规范。
## 10. Browser durable evidence 冒充 live reality

历史症状：曾出现旧 verification evidence 与当前 Browser live reality 不一致的实现缺陷。

规则：Browser READY 仍必须以当前真实 Chrome registration + live pairing / heartbeat 为真值，禁止仅凭 durable evidence 宣告 READY。该条只保留实现防伪规则；**不再要求通过 Reload、Chrome restart、Disable/Enable 或 instance drift 主动制造 Deployment E2E 用例。**

## 11. 优化问题反向阻塞已通过 Deployment

症状：主部署链已经真实 PASS，却因为 install/setup 输出噪声、措辞、timeout UX 等非阻断问题继续把 Deployment 标为 FAIL。

规则：先按冻结 PASS 条件裁决主链；不阻断主链的问题进入独立优化批次。优化版本发布后需要 npm latest smoke，但不能把 UX polish 无限扩张成新的 Deployment Gate。
