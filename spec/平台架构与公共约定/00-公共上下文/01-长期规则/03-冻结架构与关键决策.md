# 冻结架构与关键决策

## 不得重开的总原则

- Phase 3 Architecture 已 Frozen；MCP、新 runtime、测试便利性都不能作为推翻现有架构的理由。
- 不得为让测试变绿反向修改已冻结业务事实、领域边界或 Journey。
- Platform / Deployment 不得吞并 Agent、Task、Execution、Model 的 owner truth。
- 当前代码与 Frozen Spec 冲突时，先判定谁漂移；不能默认“代码就是规范”。

## Task / Journey

正式 Journey 为 J0～J6，并配套 X1～X7、Observer、Approval、Evidence、Recovery / Idempotency / UNKNOWN 等裁决。
Task durable state、Role identity、Effect、Approval 与 Recovery 的真实性必须通过真实 Journey 证明。

## Agent / Collaboration

真实 Agent 身份以 Agent Package + Custom GPT carrier + durable Role registration 为主链。
Role 与 Agent Package 一一对应；机器可确定的 gateway/state/token 等事实不能重新要求用户输入。

## Execution / Model

Execution 按硬规则 → FAST → REASON → 人工审批边界执行。
Browser Extension 属 Execution；File / Browser / Model 都应由各自 owner 提供真实能力，不通过 Platform 伪造。
FAST / REASON 共享手机算力时按串行调度处理。

## Deployment / Platform

Platform 只负责 discovery、依赖排序、调用、聚合与 package orchestration。
Module 自己闭环 setup / verify / docs / lifecycle 语义。
标准 Platform 一级命令固定为七条：`install / uninstall / status / setup / docs / start / stop`。
