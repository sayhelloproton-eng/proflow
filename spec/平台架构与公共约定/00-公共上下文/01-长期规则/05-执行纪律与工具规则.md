# 核心执行纪律与工具规则

> 性质：所有 Chat 默认必读的短版铁律。本文只定义不可越界边界；完整执行 SOP 归 `03-自动化知识库` 唯一 owner。

## 1. 授权与裁决

- 用户是重大结构、Frozen Contract、Owner/State、范围扩张的裁决者。
- “整理 / 顺手优化 / 看起来更合理”不是产品修改授权。
- 已 PASS/FROZEN 能力只有新的可复现 regression evidence 才允许局部重开。
- Real 阶段只修当前 owning blocker，禁止借机大改稳定功能。

## 2. 真值层级

```text
Formal Spec / Frozen Contract = 应该是什么
Git/source                    = 当前实现
Registry                      = 发布事实
Product Workspace             = 安装/物化事实
Browser/runtime/Owner         = 当前真实运行事实
```

源码/单测 PASS 只能证明候选；真实修复必须进入真实 artifact/Workspace 并回原场景复验。历史文档不能覆盖更晚的机械 authority。

## 3. 自动化必须模拟人工

自动化只能替代真人执行已有公开 CLI、真实 Browser/UI、真实恢复路径和等待/观察动作；不得为跑通验收直接写 `.proflow`、Owner DB、pairing evidence、node_modules 或远端资源状态。

## 4. 工具边界

```text
Repomix        = Context Plane
CodeGraph      = Structure Plane
Local Dev      = Execution Plane
Playwright/AX  = Reality Plane
```

铁律：先按当前最大不确定性选择第一 authority，不做仪式化四连调用；Browser/UI symptom Reality-first，仓库理解/修改 Context-first，纯结构可直接 CodeGraph，纯 Git/test/PID/readback 可直接 Local Dev。完整调度、Batch、信息增益规则唯一见 `03-自动化知识库/基础动作/GPT-Chat-MCP-Mac高吞吐执行规则.md`。

## 5. 仓库修改与 Reality 调试

任何仓库修改都统一遵守：

```text
BATCH_CONTEXT → PLAN_FROZEN → BATCH_TRANSFORM → BATCH_VERIFY → CLOSEOUT
```

不存在“单文件不用 Batch”的例外。Runtime/Browser 调试统一遵守：先批量观察、冻结 hypothesis/mutation budget，再做原子动作与 authority readback；必须找 `FIRST_DIVERGENCE`，不得边看边发明脚本。完整 SOP 归 `GPT-Chat-MCP-Mac高吞吐执行规则.md`，Browser 细节归 `Browser-UI自动化.md`。

## 6. Root Cause / Hotfix

`VALID_DEFECT != CURRENT_ROOT_CAUSE`。Real/SAME-SCENE 发布 hotfix 前必须形成：

```text
CURRENT_REALITY → FIRST_DIVERGENCE → owning code path → causal regression → HOTFIX_ADMITTED
```

没有因果闭环不得花 release/adoption 成本。修复后只沿原失败 checkpoint 向前；若错误不移动，必须重判根因。完整 repair/release 编排见 `流程/Package-Update-Loop.md`。

## 7. 非幂等与 UNKNOWN

publish、install/update、create remote resource、migration、Browser side effect 等发生 timeout/UNKNOWN 时，先恢复权威状态，再决定是否继续；禁止盲重试。长任务保存 Round/PID/log，低频读取，不因“暂无输出”重复执行。完整恢复法见 `基础动作/Round-PID-Log与恢复.md`。

## 8. 最小影响修复

真实自动化验收默认最小影响模式：一个已证明假设 → 一个最小行为修复 → targeted regression → 回 SAME SCENE。没有证据不得把多个候选问题打包成大修；只有现有 Frozen 语义无法表达正确行为且证据指向 SPEC_GAP/CONTRACT_CONFLICT 时才升级架构议题。

Timeout 先证明 owner 和真实延迟，禁止用简单放大 timeout 掩盖调度/composition 根因。

## 9. 发布物

真实验收只认 npm Registry 发布物及真实 Workspace adoption。local tarball/link/workspace override 不能替代真实安装；pack/tarball 只作为 publishability 诊断。Registry 与发布 SOP 见 `基础动作/npm发布与Registry回读.md`。

## 10. Browser / 安全 / 环境

- 普通 Web 默认后台 Playwright；`chrome://`、Extension privileged、系统 picker/确认框才允许短暂前台 AX/Swift + screenshot。
- Extension identity 不能靠卡片顺序/固定坐标；mutation 前必须有 fresh reality 与目标身份/几何 attestation。
- gptweb-mcp 只能由唯一正式 manager 管理；禁止私建 supervisor。runtime 细节见 `Tool-Runtime-gptweb-mcp.md`。
- 不打印、不提交 token、Bearer、API Key、credential。
- 未经授权不删除远端 Tunnel/GPT 等共享/不可逆资源。
- 用户明确的外部环境条件不得擅自升级为产品 bug。

## 11. 公共上下文维护

机械 authority、checkpoint、blocker、root cause、tool route 或稳定执行知识变化时，必须按 `01-长期规则/02-公共上下文治理规则.md` 即时写回唯一 owner。`CURRENT` 只保留当前控制面；包 SOP/基础动作/流程知识进入 `03`；Round/旧 acceptance/原始 evidence 进入 `90`。
