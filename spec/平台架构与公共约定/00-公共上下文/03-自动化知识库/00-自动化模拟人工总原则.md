# 跨项目自动化模拟人工测试方法总览

> 性质：跨项目方法总览，不是 ProFlow 执行规则 owner，也不是第二套 SOP。
> 目标：解释“为什么这样验收”；具体“怎么执行”必须进入下表唯一 owner。

## 1. 方法主循环

```text
真实用户 Journey
→ 保存失败现场
→ 找 FIRST_DIVERGENCE / owning boundary
→ 最小修复
→ changed + affected mechanical gate
→ 回 SAME SCENE 重放
→ 阶段终局再做 FULL FRESH
```

核心只有三件事：真实入口不能被内部注入替代；失败后不重复已证明成功的昂贵步骤；机械 gate 与真实 E2E 必须同时成立但不能互相冒充。

## 2. FAST REPLAY / FULL FRESH

- `FAST REPLAY`：日常 repair loop，只升级 changed/affected artifact，回原失败 checkpoint；不机械 Fresh、不重复 OAuth/GPT/Tunnel/Browser 等已 PASS 昂贵域。
- `FULL FRESH`：阶段最终验收，使用真实 latest artifact、Fresh 环境、完整用户主链和真实外部系统；不能为了提速裁剪最终 Journey。

这只是测试强度模型。ProFlow 的具体 Deployment/Real 编排分别由 `流程/Deployment-Fresh.md` 与 `流程/Real3-J0-J4.md` 拥有。

## 3. SAME SCENE

`UNKNOWN` 先恢复 authority，真实失败从最近已证明 checkpoint 恢复；非幂等 mutation 禁止盲重试。完整执行纪律由：

- `基础动作/Round-PID-Log与恢复.md`：PID/log/timeout/UNKNOWN；
- `基础动作/Chat-高吞吐本地工程执行.md`：Reality Batch、FIRST_DIVERGENCE、mutation budget、repair loop；
- 当前业务 `流程/*`：从哪个 checkpoint 继续。

## 4. UI 与 Browser

普通 Web 使用 Playwright；Chrome privileged / 系统 UI 使用 AX/Swift + screenshot。稳定 helper 只能有一条 canonical 路径，动作返回值不能替代 visible/readback evidence。

完整 UI/Browser SOP 唯一由 `基础动作/Browser-UI自动化.md` 拥有；Playwright relay、controlled group、token/runtime 恢复由 `基础动作/Tool-Runtime-gptweb-mcp.md` 拥有。

## 5. 仓库修改与工程 Gate

仓库修改统一走 `批量读 → 计划冻结 → 批量写 → 统一验证`；结构关系由 CodeGraph，当前磁盘/Git/test/build 由 Local Dev。完整 SOP 只在 `基础动作/Chat-高吞吐本地工程执行.md`；targeted gate 细节在 `基础动作/Targeted-Gate.md`。

## 6. Release / Registry / Product Workspace

真实发布、Registry exact、Product Workspace adoption 与真实 runtime reality 是不同证据层。非幂等 publish/update 发生 UNKNOWN 时先回 authority。

- npm/version/Registry：`基础动作/npm发布与Registry回读.md`
- 单包修复发布回原场景：`流程/Package-Update-Loop.md`
- Fresh Workspace：`基础动作/Product-Workspace-Fresh.md`

## 7. 性能方法

昂贵步骤必须拆 phase timing，区分产品耗时、工具/harness overhead、cold/warm cache、正常 happy path 与 recovery。先 profiling 再改并发/timeout；不能用被 harness 错误污染的总耗时作为产品基线。

历史 ProFlow timing 样本和方法形成过程已归档到 `90-历史记录/上下文治理/20260908-归类前-自动化模拟人工总原则.md`，不再进入 active execution context。
